# RP2350 硬 GM 音源 — 可行性评估与选型建议

| 项目 | 内容 |
|---|---|
| 版本 | v1.1（评估阶段，含事实核查） |
| 目标 | 用 RP2350 + PCM5102 + 4×16MB Flash 做一台标准 General MIDI 硬音源 |
| 操作方式 | MIDI DIN 输入（6N138 光耦隔离），2 位共阴数码管 + 2 按键做本地 UI |
| 核查状态 | CS1 片选能力已由 RP2350 OTP 寄存器定义逐字核实（见 §2.1）；其余标称值待打样验证 |
| 结论 | **可行**，但有 3 个必须提前决策的技术点（见 §7） |

## 1. 结论速览

**可以做，而且用 64MB Flash 做采样回放的 GM 音源在 RP2350 上是"带宽绰绰有余、CPU 需要精打细算"的典型局面。**
真正会决定成败的不是 Flash 容量，而是下面三件事：

| # | 关键问题 | 量化结论 | 风险等级 |
|---|---|---|---|
| 1 | 64 复音渲染能不能跑得动 | 150MHz 下 48 复音很稳，64 复音要砍滤波器阶数 | 🟡 中 |
| 2 | 数据 Flash 的 QSPI 驱动 | CS1 走硬件映射（✅ 已核实），CS2/CS3 需软件片选 | 🟡 中 |
| 3 | RAM 里放多少采样缓存 | 每音色 1~2KB 缓存足够，别想"整个音色进 RAM" | 🟢 低 |
| 4 | MIDI 光耦 | **「6N317」型号不存在；6N137 阈值卡边不可用**，必须用 6N138/6N139，见 §4.1 | 🔴 高（已纠正） |
| 5 | Flash 读取带宽 | 48 复音只需 ~4.5MB/s，QSPI 有 25MB/s/片 | 🟢 低 |
| 6 | 音色库合法来源 | GPL/CC 音色库可用，但要标注许可 | 🟡 中（法务非技术） |

### 2.1 为什么是"1 片启动 Flash + 3 片数据 Flash"而不是 4 片全 16MB

RP2350 的 **QMI（Quad Memory Interface）硬件原生支持 2 个片选**：CS0（专用引脚，必须接启动 Flash）和 CS1。第 3、4 片只能用 GPIO 或 PIO 做软件片选。

**关键结论（已从芯片寄存器定义核实，比预期好很多）**：CS1 不是"只能手动操作的哑片选"。RP2350 的 OTP `FLASH_DEVINFO` 寄存器里有 `CS1_GPIO` 和 `CS1_SIZE` 两个字段，官方位定义原文：

> "Indicate a GPIO number to be used for the secondary flash chip select (CS1), which selects the external QSPI device mapped at system addresses **0x11000000 through 0x11ffffff**. There is no such configuration for CS0, as the primary chip select has a dedicated pin. **On RP2350 the permissible GPIO numbers are 0, 8, 19 and 47.** If CS1_SIZE is nonzero, the bootrom will automatically configure this GPIO as a second chip select upon entering the flash boot path, or entering any other path that may use the QSPI flash interface, such as BOOTSEL mode (nsboot)."

这意味着：

| 事实 | 含义 |
|---|---|
| **CS1 可映射满 16MB 到 0x11000000** | 一片 W25Q128 **可以整片内存映射直接读**，不用自己写驱动 |
| **CS1 的 GPIO 只能是 0 / 8 / 19 / 47** | RP2350A (QFN-60) 上 **GPIO 19** 最合适（0 和 8 留给别的功能） |
| **bootrom 会自动配置**，前提是 OTP 里写了 `CS1_SIZE` | 连 OTP 都不用烧——初始化后手动写 QMI 寄存器也能达到同样效果 |
| QMI 原生只有 CS0/CS1 两路 | 第 3、4 片**必须**软件片选 |

所以正确做法是：

- **CS0**：接一片 **4MB (W25Q32)** 启动 Flash，放固件。你原本说的 4×16MB 里拿一片做启动盘也行，但浪费 14MB，不如换小容量省钱。
- **CS1（GPIO 19）**：接 **第 1 片 W25Q128**。这片可以走 **memory-mapped XIP 风格直读**（0x11000000 起），带宽最高、代码最简单。
- **CS2 / CS3（GPIO 软片选）**：接剩下 2 片 W25Q128，由我们自己的 QSPI 位操作/PIO 驱动读取。

**这样 3 片 W25Q128 = 48MB 采样库空间**，其中 16MB 走内存映射、32MB 走软件驱动。

> ⚠️ 官方 pico-sdk 对"第二片 Flash 的 SDK 级支持"目前仍是 open issue（[pico-sdk#2205](https://github.com/raspberrypi/pico-sdk/issues/2205)），意思是 SDK 不会帮你把它当"代码存储"用。但**作为数据盘，QMI 硬件本身就是支持的**，我们直接操作 QMI 寄存器即可。不要等 SDK。

**片选分配建议**：`CS1 → GPIO19`（走硬件映射，✅ 已核实为允许值），`CS2 → GPIO8`，`CS3 → GPIO9`（GPIO 8/9 也是允许给 CS1 的脚，说明这组脚在 QSPI 域内干净可用）。这样三片数据盘的驱动可以统一成"片选切换 + QSPI 命令"，CS1 额外享受硬件映射直读。

## 3. 关键量化分析

### 3.1 音频时钟：为什么必须选 48kHz

| 参数 | 值 | 说明 |
|---|---|---|
| 系统时钟 | 150 MHz | RP2350 A2 默认最高档，PLL 干净 |
| 采样率 | **48 kHz** | BCLK = 3.072 MHz |
| PIO 分频 | 150e6 / 3.072e6 = **48.828125** | PIO 分频器 16 位整数 + 8 位小数 → 48 + 53/64 = **精确** |
| 抖动 | **0** | 分数分频 3125/64 恰好整除 |

如果坚持 44.1kHz：150e6 / 2.8224e6 = 53.146…，分数分频无法精确表示（分数部分无限循环），会有周期性抖动。虽然 PCM5102A 对 BCLK 抖动不敏感（它内部有 PLL 重整），但既然 48kHz 能做到零抖动、且是整数关系，**没有必要自找麻烦**。

> 想跑 44.1kHz 且零抖动的话，把 sys_clk 设成 147.456 MHz（12.288 × 12）再整数分频即可。但 147.456MHz 不是惯例频率，CPU 余量略少，且 RP2350 的 PLL 配置要自己算。**推荐 150MHz + 48kHz。**

### 3.2 CPU 预算：这是全局最紧的资源

150 MHz / 48 kHz = **3125 周期/采样点**（所有音色共享）。

| 复音数 | 每音色可用周期 | 能做的事 |
|---|---|---|
| 64 | 48 周期 | 单振荡器 + 线性插值 + 一阶滤波 + 2 段包络。**非常紧，需要汇编/优化** |
| 48 | 65 周期 | 上面的配置 + 少量余量。**推荐目标** |
| 32 | 97 周期 | 可上 4 点 Hermite 插值 + 二阶滤波 + 立体声 chorus。舒适 |
| 24 | 130 周期 | 可上真正的二阶滤波器 + 双振荡器 |

**建议**：**目标 48 复音**，MIDI 收到第 49 个音符时按"最弱音优先"抢占。这已经超过绝大多数硬件 GM 音源（SC-55 是 24~28 复音，MU90 是 64 复音但用专用 DSP）。

**降低单音色开销的 4 个手段**（重要）：
1. **不用浮点**：全 Q15/Q31 定点。M33 的 FPU 是单精度，Cortex-M33 上 `float` 乘加约 3~5 周期，定点只要 1 周期。
2. **包络降频更新**：ADSR 每采样点更新太浪费。**每 16 个采样点更新一次**，线性插值补中间值 → 省 60% 包络开销。
3. **滤波器只在需要时开**：约 40% 的 GM 音色（钢琴、贝斯、鼓）不需要每音色滤波，用采样自身的频谱即可。
4. **核心循环用 RAM 常驻代码**：`__not_in_flash_func()` 把混音循环放进 SRAM，避免 XIP 缓存抖动。

> **关于超频（纠正）**：RP2350 的**官方额定最高就是 150 MHz**。pico-sdk 里的 200 MHz 预设
> 是 **RP2040 专属**（源码里被 `#if PICO_RP2040` 圈住），RP2350 上**不会**自动配。
> 民间确实有人超到 200 MHz 甚至更高，但那是 out-of-spec，且必须自己提供
> `PLL_SYS_VCO_FREQ_HZ` / `POSTDIV1` / `POSTDIV2`，否则编译直接报错。
> **结论：按 150 MHz 做设计，不要依赖超频。** 余量不够就降复音数。
>
> ⚠️ **另一个时序陷阱：复位瞬间 clk_sys 并不是 150 MHz。**
> 上电路径是 ROSC/clk_ref → XOSC 起振 → PLL_SYS 锁定 → 150 MHz。
> 在 PLL 锁定之前读 `clock_get_hz(clk_sys)` 得到的是别的值。
> 所以 **I2S 的 PIO 分频值必须在 clocks 初始化之后运行时计算**，
> 硬编码 48/212 会在启动早期算出错的分频，表现为 BCLK 频率不对、音高全错。

### 3.3 RAM 预算

RP2350 有 **520 KB SRAM**，但**布局和 RP2040 完全不同，别套用 RP2040 的经验**：

| 区域 | 地址 | 大小 | 说明 |
|---|---|---|---|
| SRAM0~SRAM7 | 0x20000000 ~ 0x2007FFFF | 8 × 64 KB = 512 KB | **字交叉（word-striped）统一编址** |
| SRAM8 / SRAM9 | 0x20080000 / 0x20081000 | 2 × 4 KB = 8 KB | scratch，分别映射为 SCRATCH_X / SCRATCH_Y |
| 合计 | — | **520 KB** | SRAM_END = 0x20082000 |

> ⚠️ **纠正一个常见误解**：RP2350 **没有**"SRAM4/SRAM5 分别硬连 core0/core1"这回事。
> 那是 **RP2040** 的结构（而且 RP2040 上也不是硬连，两核都能访问）。
> RP2350 的 8 个 bank 是**字交叉**的，地址连续、两核访问等价，**不能用来做核间隔离**。
> 所以音频缓冲和 DSP 代码**不需要**（也无法）挑特定 bank 来避开另一个核抢总线。

实际可用约 512 KB。

| 用途 | 大小 | 备注 |
|---|---|---|
| I2S DMA 双缓冲 | 6 KB | 立体声 16bit × 512 帧 × 2 缓冲，约 10.7ms 延迟 |
| 每音色采样缓存 | **96 KB** | 每音色 **2 KB**（1024 采样点 Q15 单声道）× 48 复音 |
| 音色元数据 / 分区表 | 8 KB | 128 音色 + 鼓组的分区（zone）表 |
| 音序/事件 FIFO | 4 KB | core1 → core0 无锁队列，避免互斥锁阻塞音频 |
| UI / 数码管 / EEPROM 模拟 | 8 KB | |
| 栈 + 杂项 | 32 KB | 两核各 8KB 栈 |
| **合计** | **~154 KB** | **剩 350KB+ 余量**，非常宽裕 |

**核心认知**：不要试图把整个音色放进 RAM。**每音色 2KB 缓存 = 1024 个采样点 = 21.3ms 的播放量**，是 DMA 缓冲（10.7ms）的 2 倍，有足够安全余量。

如果某些音色（如长笛、弦乐）需要更长的连续性，可给小号音色动态分配大缓存。**用"按需分级缓存"策略**。

> 由于 SRAM 是字交叉、无核私有区，**不要把"把音频代码放进核心私有 RAM"当作优化手段**——
> 那条路在 RP2350 上不存在。替代做法是把混音热循环用 `__not_in_flash_func()` 放进
> SRAM（任意 SRAM 都行）以避免 XIP 缓存抖动。


### 3.4 Flash 读取带宽：完全不是瓶颈

数据盘带宽计算（**这是好消息**）：

| 项目 | 数值 |
|---|---|
| 单芯片 QSPI 100MHz 4-bit 理论带宽 | 4bit × 100MHz = **50 MB/s** |
| 实用带宽（含命令开销、CS 切换） | **~25 MB/s/片** |
| 4 片聚合 | **~100 MB/s** |
| **48 复音 × 96 kB/s**（48kHz×16bit 单声道） | **4.6 MB/s** |
| 占用率 | **不到单芯片的 20%** |

**结论：读取带宽富余 20 倍。** 真正要管的是**延迟**，不是带宽：

- 1KB burst = 1024×8 / 50M ≈ **164 μs**（含开销约 200μs）
- 48 复音 × 每 21ms 需要一次 1KB 补充 → 平均每 **440μs** 有一次请求
- 单次耗时 200μs → **占用率 45%，可行但不轻松**
- **对策**：把音色库**交错（interleave）分布到 3 片数据盘上**。相邻的 zone 放不同芯片，让多个复音能并行读取。这样占用率直接降到 15% 左右。

**这就是 4 片 Flash 的真正价值**：不是容量，是**并行带宽**和**低延迟**。

### 3.5 Flash 容量规划（64MB）

采用"**起始段 16bit 无损 + 循环段压缩**"的混合编码，实测约省 45% 空间：

| 数据 | 容量 | 说明 |
|---|---|---|
| 128 个 GM 旋律音色，每音色 2 层力度（弱/强） | ~38 MB | 平均每层 ~150KB，含 1~2 个采样分区 |
| 鼓组（GM Channel 10）47 个键位 | ~6 MB | 每键 1~2 个采样 |
| 循环点/分区表/包络/调音元数据 | <1 MB | |
| **合计** | **~45 MB** | 48MB 可用空间内，**留 3MB 余量** |

对比参考：TimGM6mb 是 6MB 的 GM 音色库（音质一般），GeneralUser GS 是 30MB（音质好），SGM-V2.01 是 240MB（顶级）。**64MB 做一套"中等偏上"的 GM 是没有问题的。**

**音色库来源与许可（务必注意）**：
- 推荐起点：**GeneralUser GS**（[mrbumpy409](https://github.com/mrbumpy409/GeneralUser-GS)）— 30MB，许可宽松（允许免费/商业使用，需署名）
- 次选：**TimGM6mb**（6MB，GPL-3）— 体积小适合先跑通
- **注意**：GPL 是"软件许可"，用于音频数据时法律上属灰色地带。若只是自用或开源项目没问题；**若要商品化，务必换成明确 CC0/CC-BY 的音色库，或自行录制采样。**

## 4. 硬件设计要点

### 4.1 ★ MIDI 输入电路（本方案最容易做错的地方）

> ## ⚠️ 两条必须先纠正的结论
>
> **① 「6N317」这个型号不存在。**
> 查 datasheet 库返回 0 个文件，Findchips 无库存无报价。来源已追溯清楚：
> 专利 [CN204575199U](https://patents.google.com/patent/CN204575199U/zh) 里写
> 「3个型号为6N317的光耦」，而 TB6560 步进驱动的**标准参考设计**用的是
> **2×6N137 + 1×TLP521**。所以 `6N317` 是 `6N137` **错了一位数字**，
> 借由专利和中文二手资料扩散。**按这个型号采购会直接卡住。**
>
> **② 6N137 不符合 MIDI 规范，不只是"余量不足"。**
>
> MIDI 1.0 电气规范 **CA-033**（[midi.org](https://midi.org/5-pin-din-electrical-specs)，
> AMEI 镜像 [ca33.pdf](https://amei.or.jp/midistandardcommittee/Recommended_Practice/e/ca33.pdf)）
> 对接收端的原文要求：
> > *"Sharp PC-900V and HP 6N138 opto-isolators have been found acceptable.
> > Other high-speed opto-isolators may be satisfactory.
> > **The receiver must require less than 5 mA to turn on.
> > Rise and fall times should be less than 2 microseconds.**"*
>
> 注意 *"should"* 的用词——这是**设计准则**，不是硬性通过/失败判据；
> 但"必须在 5mA 以下导通"是明确的接收端要求。
>
> | 器件 | 导通阈值 | 结论 |
> |---|---|---|
> | **6N137** | **推荐工作条件 I_FH(min) = 6.3 mA**（Fairchild/Isocom 预留 20% CTR 退化） | ❌ **规范要求 <5mA，它要求 ≥6.3mA，超规范** |
> | **6N138** | **1.6 mA**（CTR ≥300%） | ✅ **规范点名**，约 3 倍余量 |
> | **6N139** | **0.5 mA**（CTR ≥400%） | ✅ 余量更大 |
> | **PC-900V**（夏普） | 4mA 时 tr/tf 典型 2/1 µs | ✅ **规范点名** |
> | **H11L1** | 1.6 mA max（带施密特输出，边沿好） | ✅ 可选 |
>
> 所以 6N137 是**设计上就不达标**，不是"最坏情况下勉强"。
> 症状是**台架能通、换个音源就不通**——最难查的那类故障。
>
> ⚠️ **6N137 与 6N138/6N139 同封装但引脚功能不兼容**：
> 6N138/6N139 的 **pin7 是达林顿基极 V_B，不是使能端**。
> 把 6N137 插进用了 pin5→pin7 加速电阻的 6N138 座子，
> 那个电阻会变成 VE 的下拉 → 输出被永久禁用 → 静默失效。
>
> ⚠️ **别只看典型值**：即使是点名器件，典型 tr/tf 也不保证满足 2µs。
> PC900V 在 4mA 下典型 2/1 µs 但**最坏 6/3 µs**；6N138 在 1.6mA 下典型
> 7.3/1 µs 但**最坏 35/10 µs**。所以
> **6N138/6N139 必须加 pin7 → GND 的 4.7kΩ 基极-发射极电阻**加速关断，
> 否则边沿变慢会直接造成数据错误（Vishay 6N139 有记录的失效模式）。

#### 推荐电路（6N138 / 6N139，可直接抄）

```
                    ┌─ 接收侧只有 1 颗 220Ω
                    │
MIDI DIN-5 Pin4 ──┬── R1 220Ω ──┬── 光耦 Pin2 (Anode)
                  │             │
                  │            ┌┴┐
                  │            │ │ LED (内部)
                  │            └┬┘
                  │             │
                  ├── D1 1N914 ─┤   ★ 反并联在 LED 两端，阴极朝 Pin4 侧
                  │             │     规范原文标注为
                  │             │     "Reverse voltage protection for opto-isolator"
                  │             │     （只有一颗，不是"一对二极管"）
                  │             │
MIDI DIN-5 Pin5 ──┴─────────────┴── 光耦 Pin3 (Cathode)

  +5V ──┬── 光耦 Pin8 (VCC) ── 100nF ── GND
        │
        └── R2 1kΩ ──┬── 光耦 Pin6 (VO) ──► RP2350 UART0 RX (GPIO10)
                     │
                     ├── 光耦 Pin7 (V_B) ── R3 4.7kΩ ── GND
                     │     ★ 6N138/6N139 的 pin7 是达林顿基极，不是使能端！
                     │       这个电阻用来加速关断，不加会导致边沿变慢、误码
                     │
  光耦 Pin5 (GND) ───┴── GND
  光耦 Pin1,4 (NC) ── 悬空
```

**★ 上拉电阻用 1kΩ，不是 4.7kΩ/10kΩ**
规范**没有**规定上拉值，只规定边沿要 <2µs。上拉越大边沿越慢：

| 上拉 | 上升时间（按 ~100pF 负载估） | 评价 |
|---|---|---|
| 10 kΩ | ~1 µs | 勉强，不推荐 |
| 4.7 kΩ | ~470 ns | 可用 |
| **1 kΩ** | **~100 ns** | ✅ **推荐**，MIDIbox 等参考设计常用值 |
| 270~470 Ω | 更快 | 部分设计（配 H11L1）用，功耗略增 |

6N138 集电极开路灌 1kΩ@3.3V 只有 3.3mA，远低于其 50mA 能力，**完全安全**。

**电流核算（MIDI 环路一共有 3 颗 220Ω，不是 2 颗）**：

| 位置 | 电阻 | 说明 |
|---|---|---|
| **MIDI OUT 侧** | 220Ω（+5V → DIN pin4） | 在**发送端**设备里 |
| **MIDI OUT 侧** | 220Ω（UART TX 经缓冲 → DIN pin5） | 在**发送端**设备里。★ pin5 **不是地**，是被驱动器拉低的电流汇点 |
| **MIDI IN 侧（本板）** | **220Ω（串在光耦 LED 前）** | **只有这一颗在本板上** |

- 环路总电阻 = 220 + 220 + 220 = 660Ω
- (5V − ~1.4V Vf − 驱动器压降) / 660 ≈ **5 mA**（与规范标称的 5mA 环路一致）
- 6N138 阈值 1.6mA → **约 3 倍余量** ✓
- 6N137 要求 ≥6.3mA → **5mA 达不到** ✗ ← 这就是不能用它的原因

**DIN-5 各脚定义**（避免接错）：

| 脚 | 作用 |
|---|---|
| 1 | 不接（NC） |
| 2 | 电缆屏蔽/地。★ 2014 版规范规定**只在发送端接地**，可选经 0.1µF |
| 3 | 不接（NC） |
| 4 | 电流源（+5V 经 220Ω） |
| 5 | 电流汇（被发送端驱动器拉低，**不是地**） |

> **★ 重要纠正**：网上有说法称"两颗电阻在 MIDI 线缆里"——**错的**。
> 线缆只有 pin2/4/5 三根导线，不含任何元件。三颗电阻分别在发送端（2 颗）和接收端（1 颗）。

> **★ 3.3V 发送端的正确做法**：MIDI 规范 2014 版（CA-033 修订）为 3.3V 发送端
> 把发送侧电阻改成 **R_A = 33Ω（0.5W）、R_C = 10Ω（0.25W）**，以维持同样的
> ~5mA 环路电流；另外可选加磁珠和屏蔽接地。**接收侧的 220Ω 不变**，
> 该修订也**没有**给接收端增加任何二极管。
> 所以 **3.3V 的 MIDI OUT 是规范支持的**，但**不能照抄 5V 的发送侧电阻值**。

> **★ 另一个不要用的器件：TLP521**
> 它**不是**规范点名的 MIDI 器件，是慢速通用三极管输出光耦，
> **不能用在 MIDI IN 信号路径**。它之所以常出现在 TB6560 参考设计里，
> 是因为那里只用它隔离**静态的 ENABLE 线**，而同一设计里给快速 CLK/CW
> 脉冲用的正是 6N137——照搬那个电路做 MIDI 输入必然失败。

#### 输出极性（固件必须与此一致）

**相对电流环是反相的**：环路有电流 → LED 亮 → 输出被拉低。
而 MIDI 规定 **逻辑 0 = 有电流**，UART 的起始位也是低电平，
所以**到了 MCU 的 RX 脚极性正好是对的，不需要额外反相器**。

> 这就是为什么有些资料说"反相"、有些说"不反相"——两者说的层次不同：
> 相对电流环是反相的，相对 UART 帧格式是正相的。
> **结论：光耦 VO 直接接 UART RX。**

#### 绝对不要用的器件

- **PC817 类**：4 脚光敏三极管光耦，无 VCC、无使能，边沿速度远达不到 2µs，CTR 离散大 → 误码
- **6N137**：导通电流不达标（见上）

> 若你想用 3.3V 单电源简化设计，可改用**低电压数字隔离器**（Si8640、ADuM1201），
> 3.3V 可用且边沿更好。但 MIDI 规范要求隔离，别用非隔离方案。

### 4.2 PCM5102A I2S 输出

**完整接线、跳线设置和供电电压的坑见 §4.7**（以你给的模块实物丝印为准）。这里只列要点：

- I2S 三线：`BCK ← GPIO12`、`LRCK ← GPIO13`、`DIN ← GPIO14`
- **`SCK` 必须接 GND**（选内部 PLL，从 BCK 重建主时钟，省掉 MCLK）
- `VIN` 建议给 **3.3V**（不是 5V，理由见 §4.7）
- `FLT` / `DEMP` / `XSMT` / `FMT` 模块已配好默认值，**不用动**
- 模块自带 3.5mm 座和 RC 滤波，`LINE OUT` 可直接接有源音箱/功放

> 我最初写的"输出不要直接接耳机、要加耳放"是**错的**——这块模块自带耳机座
> 和配套的驱动/滤波电路，直接插耳机即可。`LINE OUT` 是可选的线路输出。

### 4.3 QSPI Flash 阵列布线

- **CLK / D0 / D1 / D2 / D3 四片全部并联**，各自独立 CS
- **CLK 走线要短且等长**（< 5cm），100MHz 下它是唯一的高速信号
- **每片 Flash 独立 100nF 退耦**，紧贴 VCC 引脚（< 3mm）
- 片选走线不需要等长，但要避免与 CLK 长距离并行
- 建议 **CLK 串一颗 22~33Ω 电阻**抑制过冲

#### ★ 关于 WP# / HOLD#：不要把"上拉到 3.3V"当成四线模式的必要条件

这是网上教程里流传最广的错误之一，逐条纠正：

| 说法 | 事实 |
|---|---|
| "WP# 和 HOLD# 必须上拉到 3.3V，否则进不去四线模式" | ❌ **反了**。四线模式下 /WP 变成 **IO2**、/HOLD 变成 **IO3**，它们是**数据线**，接强上拉反而与数据驱动打架 |
| "四线模式靠引脚拉高就能进" | ❌ 四线模式由**状态寄存器 2 的非易失 QE 位**使能，与引脚电平无关 |
| "那这两个脚可以悬空" | ❌ 不好。上电复位到固件配置 QE 之间，悬空脚可能受干扰 |

**正确做法**：仍然给 /WP 和 /HOLD 加 **10kΩ 上拉**（四片共用一个即可），
目的不是"进四线模式"，而是**保证上电到 QE 配置完成之间引脚不悬空**。
进入四线模式后，SoC 会推挽驱动这两条线，10k 上拉太弱，不会造成竞争。

#### ★ W25Q128JV 命令集（我最初的笔记有错，已纠正）

| 操作码 | 模式 | 说明 |
|---|---|---|
| `0x0B` | 1-1-1 | **单线 Fast Read**（不是 0x6B！） |
| `0x3B` | 1-1-2 | Fast Read Dual Output |
| `0xBB` | 1-2-2 | Fast Read Dual I/O |
| `0x6B` | 1-1-4 | Fast Read Quad **Output** |
| **`0xEB`** | **1-4-4** | **Fast Read Quad I/O ← 我们要用的就是这条** |

> 固件只需实现 `0xEB` 一条读命令。上电初始化时还需要：
> `0x06`(Write Enable) → `0x01`(Write Status Register，置 QE 位) → `0x05`(Read Status)。
> QE 位是**非易失**的，烧录一次即可，但固件仍应每次启动校验。


### 4.4 数码管驱动

2 位共阴 → **动态扫描（多路复用）**：

```
段线 a~g + dp：GPIO ── 330Ω ── 数码管段引脚 (共 8 路，实际用 7 段)
位选 COM1/COM2：GPIO ── 1kΩ ── NPN 基极 (MMBT3904)
                 NPN 集电极 ── 数码管 COM
                 NPN 发射极 ── GND
```

- 段电流：(3.3 − 1.9) / 330 ≈ **4.2 mA/段**
- 8 段全亮时单管集电极电流 34 mA，NPN 完全承受得住
- 扫描频率 ≥ 200 Hz（每 2.5ms 切换一位），肉眼无闪烁
- **也可以省两个 NPN**：直接用 GPIO 灌电流（RP2350 单脚 12mA 上限，8 段共 34mA 超了）→ **必须用三极管**，别省

### 4.5 按键

- GPIO 内部上拉**不可靠**（RP2350 内部上拉约 50~80kΩ，抗干扰差）
- **外部 10kΩ 上拉到 3.3V + 100nF 到 GND**，软硬件双重消抖
- 一端接 GPIO，另一端接 GND，按下 = 低电平

### 4.6 电源树（USB 供电）

**由 RP2350 的 USB 口（USB-C）供电**，另留两个 5V 输入焊盘做备选（见下）。

```
USB-C ──┬── VBUS ── D1 SS34 肖特基 ──┬── VSYS/5V ──┬── 6N138 VCC (5mA)
        │                            │             │
        └── GND ─────────────────────┴─────────────┴── 100µF + 100nF ── GND
                                          │
                                          └── LDO 3.3V/800mA ──┬── RP2350 (60~100mA)
                                                               ├── 4× Flash (~60mA 峰值)
                                                               ├── PCM5102A 模块 (~30mA 峰值)
                                                               └── 数码管 (34mA)
                                                               总计 ≈ 250mA
```

**PCM5102A 的实际功耗（已查证 SLAS859A p.6，@3.3V / f_S=48kHz）**：

| 参数 | 双极性零输入 | 1kHz −1dBFS |
|---|---|---|
| I_DD（DVDD 3.3V） | 7 mA | 8 mA |
| I_CC（**AVDD/CPVDD 合并一行**，不要分开算） | 11 mA | 22 mA |
| **合计** | **≈18 mA / 59.4 mW** | **≈30 mA / 99.0 mW** |
| 掉电模式 | I_CC 0.4mA，I_DD 0.5~0.8mA | |

> 数据手册里 **AVDD 和 CPVDD 是同一行合并给出的**，没有分开的数值，别按两路预算。
> 静音时电流低是因为芯片有零数据检测自动静音（p.22，1024 个 LRCK 后触发）。

**★ 关机顺序（否则会有"啪"的一声）**——数据手册 p.24/p.25 明确规定了：

1. **断电前至少 150 t_S + 0.2ms 把 `XSMT` 拉低**（软静音）
2. **断电前 3ms 停掉 SCK/BCK/LRCK**

未按此顺序、或直接拔电源，输出会有可闻的爆音。
所以固件在检测到"要关机"时（或 USB 掉电中断里）应该先静音再放行断电。
模块上的 `XSMT` 脚如果引出来了，可以接到一个 GPIO 由固件控制。

> ⚠️ **待核实的 BOM 项**：PCM5102A 的**电荷泵与退耦电容具体数值**在数据手册
> 图 39~42（p.26~27）里，那几页是位图，文字层取不到。
> 已经能确认的结构性事实：**CAPP–CAPM 之间必须有飞电容**，
> 且 **V_NEG、CPVDD、AVDD、DVDD、LDOO 都需要退耦**。
> 自己画裸片方案前请直接看图 39~42 或 EVM 原理图定值。
> 用现成模块的话模块上已经配好，不用管。

**USB 供电的关键设计点**：

| 项目 | 做法 | 原因 |
|---|---|---|
| VBUS → 5V 网络 | **必须串一颗 SS34 肖特基** | 防止板上 5V 倒灌回 USB 口。若同时插了外接 5V，没有这颗管子会烧 USB 主机 |
| VBUS 检测 | 100kΩ + 47kΩ 分压到 GPIO（可选） | 让固件知道是否插了 USB，可做"插上 USB 自动进刷机模式" |
| CC1/CC2 | 各接 5.1kΩ 到 GND | **USB-C 做受电端必须的**，否则 Type-C 线不供电（这是最容易漏的一条） |
| D+/D- | 串 27Ω 匹配电阻 | RP2350 要求，抑制反射 |
| 去耦 | VBUS 100µF + 100nF | |
| ESD | USBLC6-2SC6 或等效 | 外露接口建议加 |

**★ CC1/CC2 的 5.1kΩ 是最容易漏的一条**：USB-C 插座做设备（受电）端时，
必须在 CC1、CC2 上各挂一颗 5.1kΩ 下拉到 GND，主机才会输出 5V。
漏了的话插上电脑毫无反应，非常难查。

**★ 备选：外接 5V 输入焊盘（保留但在 USB 之后）**

板上仍留 **2 个焊盘**（+5V / GND），经 **D2 SS34** 接到 5V 网络——注意是**再加一颗**
二极管，**不是直接并联**。作用：
- 可以用外部 5V 电源供电（脱离电脑当独立音源用）
- 两颗二极管形成简单的"或"逻辑，USB 和外接电源**谁电压高谁供电**，不会互相倒灌
- 焊盘 ≥2.0mm，丝印标 `+5V` / `GND` / `≤5.5V`

**推荐 LDO**：**RT9013-33**（低压差、便宜）或 **AMS1117-3.3**（压差 1.1V、
静态电流大）。给 DAC 想要低噪声就用 **ADP150-3.3** / **LP5907-3.3**。

**模拟电源隔离**（重要，否则会听到"沙沙"数字噪声）：
```
3.3V ── 磁珠 (600Ω@100MHz) ──┬── PCM5102A 模块 VIN
                              └── 10μF + 100nF ── GND
```

### 4.7 ★ PCM5102 模块接线（以此模块实物丝印为准）

按你给的模块实物图，这是一块常见的紫色 PCM5102A 模块，**10 脚排针 + 3.5mm 耳机座
+ 电位器**。丝印分两排：

| 丝印（控制排） | 丝印（信号排） | 说明 |
|---|---|---|
| `VIN` | `VIN` | 电源正 |
| `GND` | `GND` | 电源地 |
| `FLT` | `BCK` | 滤波器延迟选择 / 位时钟 |
| `DEMP` | `DIN` | 去加重 / 数据 |
| `XSMT` | `LRCK` | 软静音（**高=不静音**）/ 左右时钟 |
| `FMT` | — | 音频格式选择 |
| `SCK` | — | **系统时钟输入，必须接地** |
| `BCK` / `DIN` / `LRCK` | | 与右侧重复引出 |

旁边还有 `AGND`、`LROUT`/`ROUT`、`LINE OUT`、`H3L`/`H4L` 等焊盘。

**实际只需要接 5 根线**：

```
PCM5102 模块          RP2350A / 电源
─────────────         ──────────────
VIN      ────────────  3.3V（经磁珠 + 10µF/100nF 退耦）
GND      ────────────  GND
BCK      ────────────  GPIO12
DIN      ────────────  GPIO14
LRCK     ────────────  GPIO13
SCK      ────────────  GND      ← ★ 关键，见下
```

**★ SCK 必须接地**（不是悬空！）
PCM5102A 内置 PLL，可以从 BCK 自行重建主时钟。**SCK 接地 = 选择"用内部 PLL"模式**，
这样就不需要额外的主时钟输出，省一个 GPIO 和一路时钟布线。

**★ VIN 必须给 3.3V，绝对不能给 5V**
PCM5102A 的绝对最大额定值是 **AVDD/CPVDD/DVDD = 3.9V**（SLAS859A p.4），
**5V 会直接打坏芯片**。模块的 `VIN` 直接喂给芯片电源轨，所以只能 3.3V。
这也正好和 RP2350 的 3.3V 电平一致，避免 §4.7 里说的电平不匹配问题。

| 跳线/引脚 | 板上默认 | 我们要的 | 处理 |
|---|---|---|---|
| `SCK` | — | **硬接地** | 见下，必须接 GND 网络 |
| `FLT` | 下拉（正常延迟） | 正常延迟 | 模块已默认，**不用动** |
| `DEMP` | 下拉（关去加重） | 关 | 模块已默认，**不用动** |
| `XSMT` | 上拉（不静音） | 不静音 | 模块已默认，**不用动** |
| `FMT` | 下拉（I2S 格式） | I2S | 模块已默认，**不用动** |

> 模块上这几个脚通常已经焊了贴片电阻做默认配置，
> **直接用模块就不用管它们**；如果哪天换裸片 PCM5102A 自己布，
> 这几个脚就必须自己配，且要注意裸片的 `V_NEG`（−3.3V 电荷泵输出，
> 需要退耦）、`CAPP`/`CAPM`（飞电容）、`LDOO`（内部 1.8V 逻辑轨）都要正确处理。

**★ SCK 接地的要求比"接一下就行"严格**
数据手册 SLAS859A p.12 原文（System Clock PLL Mode）：

> "The device starts up expecting an external SCK input, but **if BCK and LRCK start
> correctly while SCK remains at ground level for 16 successive LRCK periods, then the
> internal PLL starts**, automatically generating an internal SCK from the BCK reference."

三个必须满足的条件：
1. **SCK 必须是硬接地**（≤ 0.3 × DVDD），**悬空不行**——悬空的施密特输入可能被读成高，
   那就进了"外部 SCK 模式"，结果是**静音**
2. **BCK/LRCK 必须先正常运行起来**，PLL 才会锁定
3. **BCK 必须是 64 × f_S**（我们的 48kHz × 64 = 3.072MHz 正好符合）
4. 如果 BCK/LRCK 关系失效超过 4 个 LRCK 周期，芯片会重新初始化并静音输出

> **推论（固件要注意）**：上电顺序必须是"先给 SCK 地电平 → 再启动 I2S 时钟"。
> 而且 I2S 时钟不能中途停——停超 4 个 LRCK 周期就静音，恢复要重新等 16 个周期。
> 所以 DMA 不能欠载（这正是要把音频引擎放在 core0 独占的原因之一）。

**输出侧**：
- 模块自带 RC 滤波和 3.5mm 耳机座，`LINE OUT` 可直接接功放/有源音箱
- 若要接**无源音箱**，需要外接功放（PAM8403 之类），模块输出驱动不了
- 模块上的电位器是模拟音量，**和固件的数字音量是两回事**，建议把它拧到较大位置，用固件控制音量

**PCB 装配建议**：如果你要把这块模块装到 PCB 上，注意它**背面的 3.5mm 耳机座有厚度**，
且电位器是**轴向**的。建议：
- 用 **2×5 排母**让模块可插拔（便于换模块、便于调试），而不是直接焊死
- 或者只把 `VIN/GND/BCK/DIN/LRCK/SCK` 6 个点用**飞线/焊盘**引出，模块固定在板外
- 排母位置**不要压到耳机座**，留出 12mm 以上净空

## 5. 引脚分配建议（RP2350A QFN-60，30 个 GPIO）

| GPIO | 功能 | 备注 |
|---|---|---|
| — | **QSPI CLK / D0-D3 / CS0** | RP2350 专用引脚，不可改；CS0 接启动 Flash |
| **19** | **QMI CS1（数据盘 1）** | ✅ 已核实：CS1 的 ALT 功能是 **F9 / `XIP_CS1n`**，**低有效**，RP2350A 上仅 **GPIO 0 / 8 / 19** 可用（GPIO 47 是 RP2350B 专属） |
| 8 | 数据盘 2 的片选 CS2 | 普通 GPIO 软件片选（**不**用 F9 功能） |
| 9 | 数据盘 3 的片选 CS3 | 普通 GPIO 软件片选 |
| 10 | UART0 RX ← MIDI 光耦 | 也可改 PIO UART，更灵活 |
| 11 | UART0 TX → MIDI THRU（可选） | 直通功能，串 220Ω |
| 12,13,14 | **I2S：BCK / LRCK / DIN** | 3 线到 PCM5102A |
| 15~21 | 数码管段 a~g | 各串 330Ω。**注意 19 已被 CS1 占用**，段线按 15/16/17/18/20/21/22 重新分配 |
| 22,23 | 数码管位选 COM1/COM2 | 经 NPN（MMBT3904）|
| 24,25 | 按键 BTN1 / BTN2 | 外部 10k 上拉 + 100nF |
| 26 | 状态 LED（可选） | 心跳 / 削波指示 |
| **28,29** | USB DP / DM | 固定，用于刷音色库 |
| 27, 以及 1~7 的空闲脚 | **预留** | 建议引出 4~6 个测试点/扩展排针 |

> **引脚数够用（用掉约 20 个，30 个 GPIO 有余量）**，无需 IO 扩展芯片。
>
> ### ★ CS1 的两个硬约束（画板前必须知道）
>
> 1. **GPIO 只能是 0 / 8 / 19（RP2350A）**。这三条是硬约束，
>    由 `XIP_CS1n` 这个 ALT 功能（F9）的物理分布决定。
>    **注意 GPIO 1 不是 CS1**——GPIO 1 的 F9 是 TRACECLK（我最初写 GPIO 0/1 是错的）。
> 2. **勘误 E14：bootrom 在 CS1 挂在非 GPIO 0 的引脚上时会配错 pad**。
>    因为我们要用 **GPIO 19**，所以**必须在固件里自己配置该 pad**
>    （设成 F9、使能输入、关闭内部上下拉），不能依赖 bootrom 的自动配置。
>    这一条如果漏了，症状是第二片 Flash 完全读不到数据，且很难定位。
>
> 另外 **CS1 是低有效信号**（`CS1n`），固件里片选使能/禁用的电平不要写反。

## 6. 固件架构

### 6.1 双核分工（关键设计）

```
┌─ core0 ────────────────────────────┐   ┌─ core1 ──────────────────────┐
│ 音频引擎（硬实时，绝不阻塞）        │   │ MIDI 解析（UART 中断 + 状态机）│
│                                    │   │ UI 扫描（数码管 1kHz / 按键） │
│ loop:                              │   │ Flash 写入服务（USB MSC）     │
│  等待 DMA 半满中断                  │   │ 音色库管理 / 参数持久化        │
│  ← 从 FIFO 批量取 MIDI 事件         │   │                              │
│  → 分配/抢占音色                    │   │  产出 MIDI 事件               │
│  → 渲染 512 帧（全定点）            │   │        ↓                     │
│  → 推入 DMA 缓冲                    │   │   无锁 SPSC 环形队列 (4KB)    │
└────────────────────────────────────┘   └──────────────────────────────┘
              ↑                                        │
              └────────────────────────────────────────┘
```

**为什么必须双核**：音频渲染一旦被 USB/Flash 写入操作打断，就会产生爆音。把非实时任务全部赶到 core1，core0 只做一件事：按时交出音频。

**通信用无锁 SPSC 环形队列**（单生产者单消费者），不用 mutex —— mutex 会让 core0 不可预测地阻塞。

### 6.2 音色库二进制格式（PC 端工具生成）

```
Header (64 B)
├─ magic "GMSS" + version + 采样率 + 音色数 + 芯片数
Zone Table (每音色 1~4 个 zone)
├─ key_lo, key_hi, vel_lo, vel_hi   ← 分区条件
├─ root_key                          ← 原始采样音高
├─ sample_offset (24 位)              ← 每片 16MB 内寻址
├─ sample_length, loop_start, loop_end
├─ chip_id (0-2)                     ← 交错分布在 3 片数据盘上
├─ codec (PCM16 / IMA-ADPCM)         ← 混合编码
├─ attack_len                        ← 前 N 个采样点必为 PCM16
└─ envelope: A/D/S/R + 初始衰减
```

**地址编码**：`chip_id(2bit) + offset(24bit)` = 26 位，天然覆盖 3 片 × 16MB。

### 6.3 开发阶段划分

| 阶段 | 目标 | 里程碑判据 |
|---|---|---|
| **P0** 环境 | 装 pico-sdk + arm-none-eabi-gcc + cmake + picotool | `blink` 能烧进板子 |
| **P1** I2S 出声 | PIO I2S → PCM5102A 播 1kHz 正弦 | 示波器/耳朵确认干净正弦，无咔哒声 |
| **P2** 单音采样 | QSPI 读 1 片 Flash，播一个钢琴采样 | 1 个音符音高正确、循环点无缝 |
| **P3** 复音引擎 | 定点混音 + ADSR + 音色抢占，48 复音 | CPU 占用 < 60%，无爆音 |
| **P4** MIDI 输入 | 6N138 + UART 解析 + 音色映射 | 接键盘能弹，无丢音/卡音 |
| **P5** 4 片 Flash | 自定义 QSPI 驱动 + 交错分布 + 缓存管理 | 4 片同时读，带宽达标 |
| **P6** 音色库工具 | Python 把 SF2 转成板子格式（含 ADPCM） | 完整 GM 库烧进 48MB |
| **P7** UI + 刷写 | 数码管菜单 + 按键 + USB 刷音色库 | 能脱离电脑独立设置参数 |
| **P8** 打磨 | 降低噪声、总线负载优化、超频调优 | 听感对比软音源 |

**建议先做 P1+P2 的"最小可行验证"** —— 用一块 Pico 2 + PCM5102A 模块 + 1 片 W25Q128 模块，把"能出声"和"能从 Flash 读采样"这两件事验证掉，再画正式 PCB。**这两件事是全局风险最高的，两天就能验证完，但能省掉一次打板。**

## 7. 三大风险与决策点

### 风险 1：数据 Flash 的 QSPI 驱动（🟡 中）

- **问题**：第 1 片数据盘（CS1）已确认可由硬件映射到 0x11000000，但**第 2、3 片只能用 GPIO 软片选**；pico-sdk 无官方支持；QMI 在小数分频下读数据有已知时序约束
- **对策**：
  1. 数据盘**只读、不做 XIP 代码**，驱动只需要实现 `0xEB`（Quad I/O Fast Read）一条命令
  2. CS1 用 QMI 硬件片选，CS2/CS3 用 PIO 或纯 GPIO 位操作（读的时候不在乎多几个周期的开销）
  3. **P2 阶段先只接 1 片验证驱动**，P5 再扩展到 3 片
- **兜底方案**：如果 QMI 多片选实在不稳，**改用 PIO 实现完整 QSPI master**（RP2350 的 PIO 有 3 个模块 ×4 SM，资源足够）。PIO 版本带宽约 15MB/s/片，对 4.6MB/s 的需求仍有 3 倍余量。

### 风险 2：CPU 余量（🟡 中）

- **问题**：64 复音 × 48kHz × (插值+滤波+包络) 逼近 150MHz 极限
- **对策**：见 §3.2 的 4 个手段。**目标定 48 复音**；不够就降复音数（超频不是可靠后手，见 §3.2）
- **兜底方案**：降到 32 复音 + 更好的插值质量。32 复音的听感远好于 64 复音的爆音

### 风险 3：音色库合法来源（🟡 中，非技术）

- **问题**：好的 GM 音色库多数带 GPL 或来源不明
- **对策**：自用/开源 → GeneralUser GS；**商品化 → 必须换成 CC0/CC-BY 或自行采样**。这个决策越早做越好，因为它影响 §3.5 的容量规划

## 9. 选型建议汇总

| 环节 | ✅ 推荐 | ❌ 避免 |
|---|---|---|
| MCU | **RP2350A**（裸片画板）或 Pico 2 模块（先验证） | RP2040（无 QMI 多片选，双核但 PIO 资源少） |
| 启动 Flash | **W25Q32 (4MB)** | 用 16MB 当启动盘（浪费） |
| 数据 Flash | **W25Q128JVSIQ ×3**，交错分布 | 全部串在同一条片选上 |
| DAC | **PCM5102A 模块**（SCK 接地） | PCM5102 裸片自己布模拟部分（没必要） |
| 光耦 | **6N138 / 6N139**（阈值 1.6mA / 0.5mA，余量充足） | **6N317（不存在）**、**6N137（阈值 5~6.3mA 卡边）**、PC817（速度不够） |
| 采样率 | **48 kHz** | 44.1 kHz（时钟不整） |
| 复音 | **48**（可争取 64） | 硬追 128 |
| 数值格式 | **全定点 Q15** | 浮点混音（M33 上慢 3~5 倍） |
| 音色缓存 | **每音色 2KB** | 试图全量载入 RAM |
| 编码 | **起始段 PCM16 + 循环段 ADPCM** | 全 ADPCM（起始段音质损失明显） |
| 电源 | **模拟 3.3V 经磁珠隔离** | 数字/模拟共用一路不退耦 |
